## Build-risk fixes

1. Removed the old large-file FormData upload route. Vercel Functions should not receive 500 MB file bodies; the new flow uses a short-lived V4 signed Storage PUT URL and a small commit request.
2. Fixed missing `fail` import in card deposit API.
3. Fixed Firestore checkout transaction ordering so reads happen before writes.
4. Removed remaining global `FirebaseFirestore.*` type dependencies where a direct inferred/query type is safer.
5. Added missing Firestore indexes for product/category sorting and system announcements.
6. Added complete `.env.example` coverage for all `process.env.*` usages.
7. Removed interactive `Link` → `Button` nesting in the main UI.
8. Added direct file-download redirect so the order page does not show raw JSON.

## Security fixes / checks

- No hard-coded provider secrets or Firebase service-account private key.
- Public product API removes `fileStoragePath`.
- ACC credentials are encrypted at rest.
- Order delivery decrypts ACC data only after authenticated ownership check.
- Client cannot directly mutate wallet balance, admin claim, payment state or inventory state through the application API.
- Admin APIs require Firebase custom claim `admin=true` server-side.
- Checkout is server-authoritative for price/discount/stock and requires `Idempotency-Key`.
- SePay webhook verification uses configured API key or HMAC-SHA256 with timestamp replay protection.
- NAPPay response signatures are verified before crediting wallet.
- Card serials are hashed for duplicate detection; encrypted card credentials are deleted after successful credit.
- Private files require completed order ownership and are returned as short-lived signed URLs.
- Security headers include `nosniff`, frame denial, referrer policy, permissions policy, COOP and HSTS.

## Remaining external verification

The sandbox cannot reach the npm registry and only has Node 22 locally, so the exact Node 24 dependency graph could not be installed here. A real Vercel deployment must still execute `npm install`, `npm run typecheck`, `npm run lint`, and `npm run build`.

Payment providers also require real credentials/configuration and a controlled low-value staging test. No fake payment-success path is used as a substitute.
